# Битрикс24: каталог товаров и цены (дополнение форка)

Методы доступны в модуле `OPI_Bitrix24` (русская BSL-версия и OneScript).

## Методы

| Функция | REST |
| --- | --- |
| ПолучитьСписокКаталогов | catalog.catalog.list |
| ПолучитьСписокТоваровКаталога | catalog.product.list |
| ПолучитьТоварКаталога | catalog.product.get |
| СоздатьТоварКаталога | catalog.product.add |
| ИзменитьТоварКаталога | catalog.product.update |
| УдалитьТоварКаталога | catalog.product.delete |
| ПолучитьПоляТовараКаталога | catalog.product.getFields |
| ПолучитьСписокЦенКаталога | catalog.price.list |
| ПолучитьЦенуКаталога | catalog.price.get |
| СоздатьЦенуКаталога | catalog.price.add |
| ИзменитьЦенуКаталога | catalog.price.update |
| УдалитьЦенуКаталога | catalog.price.delete |
| ИзменитьЦеныТовараКаталога | catalog.price.modify |
| ПолучитьТипыЦенКаталога | catalog.priceType.list |

Все методы используют стандартную для проекта авторизацию: адрес входящего вебхука либо домен портала и OAuth-токен. Для операций над каталогом у пользователя/вебхука должны быть необходимые права и scope `catalog`.

### Пример: добавить номенклатуру

```bsl
URL = "https://example.bitrix24.ru/rest/1/WEBHOOK_TOKEN/";

Каталоги = OPI_Bitrix24.ПолучитьСписокКаталогов(URL);
// Используйте действительный iblockId из каталога нужного портала.

ПоляТовара = Новый Структура;
ПоляТовара.Вставить("iblockId", 14);
ПоляТовара.Вставить("name", "Кабель USB-C");
ПоляТовара.Вставить("xmlId", "uid-from-1c");
ПоляТовара.Вставить("active", "Y");

СозданныйТовар = OPI_Bitrix24.СоздатьТоварКаталога(URL, ПоляТовара);
```

### Пример: создать цену

```bsl
ПоляЦены = Новый Структура;
ПоляЦены.Вставить("productId", 125);
ПоляЦены.Вставить("catalogGroupId", 1);
ПоляЦены.Вставить("price", 890);
ПоляЦены.Вставить("currency", "RUB");

СозданнаяЦена = OPI_Bitrix24.СоздатьЦенуКаталога(URL, ПоляЦены);
```

ID товаров и видов цен в примерах условные. Используйте идентификаторы, полученные от API вашего портала.

### Пример: обновить все цены товара

`catalog.price.modify` принимает поле `fields` с вложенным объектом `product`, содержащим `id` и массив `prices`. Передавайте его целиком через `ИзменитьЦеныТовараКаталога(URL, СтруктураПолей)`.

## Правила для будущей синхронизации с 1С

- Храните соответствие `СсылкаНоменклатуры/Характеристика` ↔ `product.id`; `xmlId` удобен для первичного поиска, но для обновлений предпочтительно хранить постоянный ID.
- Обрабатывайте пагинацию `list` с параметром `Отступ`. В REST Bitrix24 страница может содержать не все записи.
- Не путайте `productId`, `catalogGroupId` и ID записи `catalog.price`: обновление цены требует ID самой записи цены.
- Повторная отправка после сетевого таймаута не должна создавать дубликаты.
- Ведите журнал операций и не сохраняйте секреты вебхуков в исходном коде.
- Если используются характеристики/вариации, проверяйте отдельные `catalog.product.sku.*` / `catalog.product.offer.*` API до проектирования сопоставления.

**Ограничения:** текущая доработка только оборачивает REST-запросы. Автоматического обмена с УТ 11, теста на реальном портале, синхронизации SKU/остатков и полной англоязычной/CLI генерации в этом PR пока нет.
